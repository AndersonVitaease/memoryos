# ADR-016 — Base44 Connector Expansion (B44-EXP)

**Status:** DRAFT (proposta)
**Data:** 2026-08-04
**Relacionados:** RFC-009, ADR-015 (Safety Gate), ADR-013 (MS Graph Capability Executors), ADR-014 (Provider Router)

## Contexto

O `Base44Connector` (v2.0.0, Beta-02 PCS) expoe 15 capabilities read-only.
O SDK Base44 suporta escritas em entidades, integracoes Core (LLM, upload,
geracao de imagem/video/speech, transcricao), gestao de usuarios, workflows e
analytics — mas o conector nao expoe nada disso. O pipeline chama
`base44.entities.X.create` e `base44.integrations.Core.*` direto, bypassando
o conector (sem observabilidade do UCRBridge, sem enriquecimento do
Execution Intelligence, sem trava do Safety Gate).

## Decisao

Evoluir o `Base44Connector` em 6 fases aditivas (B44-EXP-01 a B44-EXP-06),
cobrindo +23 capabilities (15 → 38). Mesmo padrao do GitHub (multi-conta + 6
upgrades) e do Microsoft Graph (Capability Executors, embora aqui sem
extrair para executors — manter o switch).

### Decisoes arquiteturais

1. **Manter o switch `_dispatch`** — NAO extrair para executors (Fase 0
   opcional, nao recomendada). O conector ja implementa `IProductionConnector`
   (PCS) que e a "interface rica"; executors adicionariam indirecao sem
   beneficiar o PCS. Reabrir se passar de ~50 cases.

2. **Declarar `capabilityReversibility`** — Base44 foi pulado em EI-01 (todas
   safe). Ao adicionar escritas, DEVE declarar: `entities.delete` =
   `irreversible`, `entities.create/update/bulkCreate/bulkUpdate` =
   `reversible`, `users.invite/auth.updateMe/workflows.activate/deactivate` =
   `reversible`, integracoes/analytics/workflows.list/connectors.* = `safe`.

3. **Aditivo apenas** — cases novos no final do switch antes do `default`;
   `CAPABILITIES` array e `capabilityReversibility` map crescem; mappings no
   `GoalCapabilityRegistry` antes do bloco `general.*`. As 15 capabilities
   existentes ficam 100% intocadas.

4. **Nenhum caller migrado nesta RFC** — o `ConversationPipeline` e o
   `ConnectorGoalIntentExecutor` (ja no EI-04) continuam funcionando.
   Migrar chamadas diretas `base44.entities.X.create` / `Core.*` para as
   novas capabilities e EI-04 sub-step, deferido apos as fases.

5. **Cada fase independente e testavel** — nenhuma fase depende de outra.
   Ordem (1 Entity Writes → 2 Integracoes → 3 Users → 4 Connectors → 5
   Workflows → 6 Analytics) e so recomendacao de impacto.

## Alternativas rejeitadas

- **(A) Extrair para Capability Executors (Fase 0 obrigatoria)** — rejeitada:
   over-engineering para 15→38 cases. O switch ja e bem-estruturado e o PCS
   e a interface rica. Extracao fica como opcional se passar de ~50 cases.
- **(B) Criar conector separado `Base44IntegrationsConnector`** — rejeitada:
   cria paralelo (dead-end recorrente do projeto). As integracoes Core sao do
   mesmo SDK, mesmo auth, mesma identidade — pertencem ao `Base44Connector`.
- **(C) Nao declarar `capabilityReversibility` (deixar safe implicito)** —
   rejeitada: `entities.delete` e irreversivel; sem declarar, o Safety Gate
   nao freia. EI-01 exige o campo para qualquer conector com escritas.
- **(D) Migrar callers vivos nesta RFC** — rejeitada: migrar o
   `ConversationPipeline` agora colocaria rede de seguranca sobre fluxos
   automatizados sem contexto real (mesma decisao de EI-04 Option C).
   Migracao e sub-step separado, pos-fases.

## Consequencias

- **Positivas:** +23 capabilities unificadas pelo conector (observabilidade +
  enriquecimento + safety). Chat pode criar/atualizar/deletar entidades,
  chamar LLM, gerar imagem/video, convidar usuarios, listar conectores,
  gerenciar workflows — tudo via cadeia ADR-015.
- **Negativas:** switch do `_dispatch` cresce (~50 cases no final). Se ficar
  dificil de manter, extracao para executors (Fase 0) vira obrigatoria.
- **Neutras:** `capabilityReversibility` agora e declarado — Safety Gate
  passa a operar sobre `base44.entities.delete` (irreversible) quando
  chamado via `processCapability`. Callers diretos nao passam pelo gate
  (documentado; migracao e EI-04 sub-step).

## Invariants

- As 15 capabilities existentes: mesmos IDs, mesma assinatura, mesmo
  comportamento. Zero rename.
- `IProductionConnector` (connect, disconnect, isAuthenticated, health,
  metrics, diagnostics, certification, logExecution) — intocado.
- `ConnectorBootstrap` registra pela classe `Base44Connector` — import
  inalterado, mesmo `id`.
- `UCRBridge` e `PipelineObservationBridge` envolvem automaticamente.
- Aditivo apenas: nada apagado que estivesse em uso.
