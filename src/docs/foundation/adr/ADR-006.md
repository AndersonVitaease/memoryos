# ADR-006 — Memory Engine Legado: Estratégia de Deprecação
**ADR-ID:** ADR-006
**Título:** Memory Engine Legado (47 arquivos JS): Estratégia de Deprecação
**Data:** 2026-07-11
**Status:** Proposed
**DAP de origem:** DAP-06
**Sprint:** SPR-ADR-01

---

## 1. Contexto

### Por que a decisão existe

`src/lib/memory-engine/` contém 47 arquivos JavaScript implementando um Memory Engine completo com: retrieval, consolidation, lifecycle, embedding, vector index, relationships, versioning, learning, semantic retrieval, hybrid retrieval, context building, conflict resolution, deduplication, audit e policy engine.

Simultaneamente, `src/lib/memory-engine-v1/` (EF-12) é o módulo oficial certificado com 28 cenários e responsabilidade única: transformar Learnings aprovados em Memory imutável.

O produto NÃO usa nenhum dos dois. Persistência é feita diretamente nas entidades Base44 via `base44.entities.*`.

A coexistência de dois módulos com nomes similares cria risco de uso acidental do legado em código futuro.

### Componentes afetados

- `src/lib/memory-engine/` — 47 arquivos JavaScript a deprecar
- `src/lib/memory-engine-v1/` (EF-12) — módulo oficial a manter
- `src/pages/MemoryEngine.jsx` e `src/pages/MemoryEnginePage.jsx` — páginas de validação que podem referenciar um ou outro
- `src/components/memory-engine/` — componentes de teste (9 TestRunners)
- Entidades Base44: Message, KnowledgeEntity, Decision, Task, Topic — storage permanente

### Evidências do código

- `src/lib/memory-engine/` — 47 arquivos JS (memoryEngine.js, memoryRetrieval.js, memoryConsolidationManager.js, memoryLearningManager.js, etc.)
- `src/lib/memory-engine-v1/MemoryEngine.ts` — EF-12 oficial, TypeScript
- `src/lib/memory-engine-v1/memoryEngineTests.ts` — 28 cenários
- PRODUCT-FLOW-MAPPING — produto usa `base44.entities.*` diretamente, não os Memory Engines
- AUDIT-Sprint0 §5.4 — duplicação confirmada
- ARCHITECTURE-VALIDATION-REPORT §2.14 — Memory Engine legado: ❌ SRP não cumpre

---

## 2. Problema

### Conflito existente

Dois módulos nomeados `memory-engine` com semânticas completamente diferentes:

- `memory-engine/` (legado): Motor de memória completo com 15+ responsabilidades (retrieval, embedding, vector, consolidation, versioning, relationships, lifecycle, learning, semantic, context, conflict, dedup, audit, policy, hybrid)
- `memory-engine-v1/` (EF-12): Motor de memória com responsabilidade única (Learnings → Memory imutável)

O legado viola SRP massivamente. O oficial cumpre SRP. Ambos têm "memory-engine" no nome.

### Por que impede o congelamento

NB-02 no FREEZE-CHECKLIST (não-bloqueante, mas recomendado). Embora não bloqueie o congelamento, afeta RA-02 (risco alto: código futuro pode acidentalmente usar o legado). Adicionalmente, as 9 páginas TestRunner em `src/components/memory-engine/` e `src/pages/MemoryEngine.jsx` precisam ter suas referências verificadas — se apontam para o legado, persistem em produção após deprecação.

## 3. Alternativas

### Alternativa A — Deprecar imediatamente (marcar + sprint de remoção futura)

**Fase 1 (imediata — editorial):**
- Adicionar `@deprecated` JSDoc no topo de cada arquivo em `memory-engine/`
- Adicionar arquivo `DEPRECATED.md` em `src/lib/memory-engine/`
- Verificar imports em `src/pages/MemoryEngine.jsx` e `src/components/memory-engine/`

**Fase 2 (sprint posterior):**
- Remover `src/lib/memory-engine/` completamente
- Migrar TestRunners para usar `memory-engine-v1/` se necessário

**Vantagens:**
- Fase 1 é editorial, sem risco de regressão
- Sinaliza claramente o estado para desenvolvedores futuros
- Fase 2 pode ser executada a qualquer momento

**Desvantagens:**
- 47 arquivos permanecem no bundle até Fase 2
- Se TestRunners em `components/memory-engine/` usam o legado, eles quebram após Fase 2

**Impacto:** Zero no produto (produto não usa nenhum dos dois).

**Risco:** Baixo — desde que imports sejam verificados antes da Fase 2.

**Esforço estimado:** Fase 1: 1 hora. Fase 2: 0.5 sprint (remoção + verificação de imports).

---

### Alternativa B — Aguardar INT-06 (Memory Engine EF-12 integrado ao produto) antes de deprecar

**Como funciona:** Aguardar até que `memory-engine-v1/` (EF-12) esteja ativo no produto (Fase 5 do roadmap). Somente então deprecar o legado. Até lá, ambos coexistem.

**Vantagens:**
- Elimina risco de remover código que pode ter referências não detectadas
- Deprecação validada contra produto ativo com EF-12

**Desvantagens:**
- 47 arquivos persistem até INT-06 (pode ser longo)
- Risco RA-02 permanece por todo esse período: código futuro pode usar legado acidentalmente
- TestRunners em `components/memory-engine/` continuam apontando para legado

**Impacto:** Status quo mantido por mais tempo.

**Risco:** Médio — RA-02 permanece.

**Esforço estimado:** Zero agora; mesma da Alternativa A depois.

---

### Alternativa C — Arquivar (mover para `_deprecated/`)

**Como funciona:** Mover `src/lib/memory-engine/` para `src/lib/_deprecated/memory-engine/`. Não deletar.

**Vantagens:**
- Preserva histórico
- Imports quebram imediatamente (detecta referências vivas)
- Não está no path normal de imports

**Desvantagens:**
- Arquivos continuam no bundle (Vite pode incluir se há imports)
- `_deprecated/` cria nova convenção não documentada no projeto
- Imports quebrados podem ser difíceis de rastrear em 47 arquivos

**Impacto:** Médio — qualquer import existente quebra imediatamente.

**Risco:** Médio — pode revelar referências não conhecidas que causam erros de build.

**Esforço estimado:** 0.5 hora (move) + tempo de debug se imports quebram.

## 7. Recomendação Técnica

**Recomendação: Alternativa A, Fase 1 imediatamente**

Fundamentação:

1. Fase 1 é editorial (adicionar `@deprecated` e `DEPRECATED.md`) — zero risco de regressão
2. Sinaliza o estado para qualquer desenvolvedor que abra o diretório
3. Verifica imports nas páginas de validação — ação de descoberta necessária independente da alternativa
4. Fase 2 pode ser incluída em INT-06 naturalmente (quando EF-12 estiver no produto, remover legado)
5. Alternativa C tem risco de quebrar build sem inventário completo de imports

**Ação mínima para endereçar NB-02:**
1. Criar `src/lib/memory-engine/DEPRECATED.md` com: "Este módulo está deprecado. Use src/lib/memory-engine-v1/ (EF-12)."
2. Verificar `src/pages/MemoryEngine.jsx` e `src/components/memory-engine/` para identificar referências ao legado
3. Declarar `src/lib/memory-engine-v1/` como canonical em documentação

*Esta recomendação não constitui aprovação. A decisão final deve ser tomada por humano.*
