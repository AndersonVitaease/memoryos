# RFC-002 — Minimum Sufficient Context Principle (MSC)

**Status:** Accepted  
**Categoria:** Architectural Principle  
**Prioridade:** High  
**Foundation:** v1.0  
**Data:** 2026-07-11  
**Autor:** MemoryOS Engineering

---

## Objetivo

Formalizar oficialmente o princípio do **Minimum Sufficient Context (MSC)**.

Este documento NÃO cria novos componentes.  
NÃO altera o Core.  
NÃO altera o Runtime.  
NÃO altera o Roadmap.

Seu objetivo é registrar um princípio que deverá **orientar todas as futuras implementações** do MemoryOS.

---

## Contexto

Durante a evolução da Foundation foi identificado que o maior custo computacional em sistemas de IA não é armazenar conhecimento.

O maior custo é **recuperar e enviar contexto desnecessário ao modelo**.

Portanto, o objetivo do MemoryOS não é minimizar informação.

O objetivo é selecionar o **menor conjunto de conhecimento capaz de produzir uma decisão correta**.

---

## Princípio

> **O MemoryOS deverá sempre construir o Minimum Sufficient Context.**

Ou seja: o menor contexto possível capaz de preservar:

- precisão
- segurança
- explicabilidade
- qualidade da decisão

---

## Filosofia

O MemoryOS **NÃO** deverá buscar:

> "o menor contexto possível."

Ele deverá buscar:

> "**o menor contexto suficiente.**"

Esta diferença passa a ser um **princípio oficial da Foundation**.

A distinção é crítica: um contexto excessivamente pequeno compromete a decisão. Um contexto desnecessariamente grande compromete a eficiência. O MSC é o ponto de equilíbrio entre os dois.

---

## Responsabilidades

Este princípio deverá orientar:

| Componente | Responsabilidade MSC |
|---|---|
| **Goal Engine** | Extrair apenas os critérios de aceitação relevantes para o Goal ativo |
| **Context Builder** | Montar o contexto mínimo suficiente para cada consulta |
| **Planner** | Selecionar apenas os Knowledge Packages necessários ao plano |
| **Planning Intelligence Engine** | Avaliar candidatos de plano com o menor conjunto de métricas necessário |
| **Specialist Router** | Descobrir specialists com base em cobertura de domínio, não em varredura total |
| **Strategy Fusion Engine** | Fundir apenas as estratégias relevantes ao Goal, descartar com justificativa |
| **Working Memory** | Manter somente itens ativos e relevantes; promover para histórico quando inativo |
| **Connector Runtime** | Solicitar apenas os escopos OAuth necessários para a operação em curso |

---

## Critérios de Seleção de Contexto

A construção do contexto deverá considerar:

1. **Objetivo** — o Goal ativo e sua intenção primária
2. **Contexto de identidade** — userId, projectId, sessionId
3. **Journey ativa** — etapas em andamento e dependências
4. **Knowledge Packages relevantes** — somente os mapeados ao domínio do Goal
5. **Specialists envolvidos** — somente os selecionados pelo Specialist Router
6. **Capabilities necessárias** — somente as requeridas pela operação
7. **Connectors necessários** — somente os com escopos para a ação solicitada
8. **Políticas** — restrições de segurança e privacidade aplicáveis
9. **Auditoria** — trilha mínima necessária para rastreabilidade
10. **Restrições** — limitações declaradas no IdentityContext

**Regra:** Nunca utilizar conhecimento irrelevante.

---

## Reutilização

Sempre que existir conhecimento previamente validado, o sistema deverá reutilizá-lo, evitando reconstrução desnecessária.

**Exemplo:** Se um Goal foi processado anteriormente com o mesmo IdentityContext e os critérios não mudaram, o sistema deverá recuperar o resultado cacheado antes de reprocessar.

Esta política reduz custo computacional e aumenta consistência.

## Semantic Context Compression

### Definição Oficial

> **Semantic Context Compression** é o processo de transformar grandes volumes de conhecimento em um conjunto mínimo de fatos relevantes, preservando o significado necessário para tomada de decisão.

### Princípios da Compressão

- A compressão **nunca** deverá remover conhecimento essencial
- A compressão deverá preservar relações causais entre fatos
- A compressão deverá ser reversível — o conhecimento original permanece armazenado
- A compressão deverá ser auditável — o que foi incluído e o que foi excluído deve ser registrado

### Exemplo

**Antes da compressão:**
```
Documento ANVISA: 847 páginas de regulamentação sobre suplementos alimentares.
```

**Após Semantic Context Compression:**
```
[Compressed] Suplemento vitamínico: requer RDC 243/2018. Categoria: notificação.
Prazo estimado: 30 dias. Documentos: laudo técnico, rotulagem, responsável técnico.
```

O conhecimento essencial é preservado. O ruído é eliminado.

---

## Objetivo Computacional

O MSC deverá reduzir:

| Dimensão | Objetivo |
|---|---|
| Tokens | Reduzir tokens enviados por consulta |
| Custo de inferência | Reduzir custo por operação de LLM |
| Latência | Reduzir tempo de resposta |
| Consumo de memória | Reduzir Working Memory footprint |
| Processamento | Reduzir ciclos de CPU por operação |

**Garantia:** Nenhuma dessas reduções deverá comprometer a qualidade da decisão.

---

## Métricas

Toda implementação que aplica MSC poderá medir:

| Métrica | Definição |
|---|---|
| **Context Reduction Ratio** | `(tamanho_original - tamanho_comprimido) / tamanho_original` |
| **Knowledge Reuse Ratio** | `consultas_reutilizadas / total_consultas` |
| **Context Precision** | `fatos_relevantes_usados / total_fatos_no_contexto` |
| **Retrieval Precision** | `documentos_relevantes_retornados / total_documentos_retornados` |
| **Decision Accuracy** | `decisões_corretas / total_decisões` |

Estas métricas são **opcionais** nesta versão e serão obrigatórias a partir do momento em que o módulo de Learning estiver ativo.

---

## Relação com Outros Princípios da Foundation

| Princípio | Relação com MSC |
|---|---|
| **Identity Context Isolation** | O IdentityContext define o escopo do contexto — nunca vazar dados de outro usuário |
| **Event-Driven Architecture** | Eventos carregam o contexto mínimo necessário para o handler |
| **Deterministic Logic** | Decisões determinísticas requerem contexto preciso, não extenso |
| **Human Approval Gates** | Aprovação humana é ativada quando o MSC é insuficiente para uma decisão segura |
| **Explainability** | O que foi incluído no contexto e por que deve ser sempre justificável |

---

## Declaração Final

O MemoryOS passa oficialmente a adotar o princípio do **Minimum Sufficient Context**.

A plataforma deverá crescer indefinidamente em conhecimento sem que o custo computacional cresça proporcionalmente.

A escalabilidade será obtida através da **seleção inteligente do contexto** e não pela redução indiscriminada da informação.

Este princípio representa a maturidade arquitetural do MemoryOS: um sistema que sabe não apenas o que conhece, mas **o que é necessário conhecer em cada momento**.
