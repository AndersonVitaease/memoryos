### 🟡 IMPORTANTE — Drift de dados (não bloqueia, mas compromete integridade)

#### P-02: Campo `ChatSession.message_count` não está sendo incrementado
- **Problema:** As sessões existentes mostram `message_count: 0`, mas há mensagens gravadas na entidade `Message` com `session_id` correto.
- **Impacto:** Qualquer lógica que use `message_count` para decidir se uma sessão tem histórico vai falhar silenciosamente.
- **O que investigar:** `src/lib/conversation-platform/ConversationSessionManager.ts` — verificar se o incremento do contador está sendo chamado após `Message.create()`.
- **Sugestão de fix:** Adicionar `ChatSession.update(sessionId, { message_count: count + 1 })` após cada persistência de mensagem.

#### P-03: Entidade `ChatMessage` obsoleta ainda existe no schema
- **Problema:** A entidade `ChatMessage` existe no schema (`base44/entities/ChatMessage.jsonc`) mas nenhum dado é gravado nela. O sistema usa `Message`.
- **Impacto:** Confusão para qualquer IA ou desenvolvedor que ler o schema e não souber qual entidade é a ativa.
- **O que fazer:** Ou deprecar formalmente `ChatMessage` com um comentário no schema, ou deletar a entidade se não houver nenhuma referência ativa no código.
- **Arquivo:** `base44/entities/ChatMessage.jsonc`
